Phase 3.1 — Network identity Done

  • Magic bytes: [0x59, 0x4F, 0x4C, 0x4F] — ASCII "YOLO" so a p2p capture instantly identifies the network. Distinct from Ergo mainnet [1,0,2,4] and testnet [2,3,2,3] — nodes drop each other's packets at the framing layer.
  • Address prefix: 0x20 — distinct from Ergo mainnet 0x00 and testnet 0x10 so wallets reject cross-network addresses at decode time.
  • New variants: Network::SigmaChainTestnet, NetworkPrefix::SigmaChainTestnet, parses from "sigmachain-testnet".

Phase 3.2 — Block timing + voting epochs Done

  • Block interval: 20 s (per emission.es blocksPerHalving = 1,577,880 ~1 year).
  • Difficulty epoch: 6,144 blocks = 1024 × 120/20 → preserves Ergo mainnet's ~34 h wall-clock adjustment cadence.
  • Voting epoch: 6,144 blocks, aligned with the difficulty epoch (matches Ergo mainnet's 1024/1024 alignment).
  • Sync-tip freshness: 200 min (= 600 × 20 s), matching Ergo mainnet's window. No EIP-37, no v1 → v2 transition (launch at Interpreter60Version).

Phase 3.3 — Emission curve math layer Done

New YoloEmissionParams + EmissionCurve enum on ChainSpec. The Ergo linear curve and YOLO geometric-halving curve coexist; the chain selects via EmissionCurve::ErgoLinear or EmissionCurve::Yolo(...). Per-height helpers (yolo_emission_at_height, yolo_miners_reward_at_height, etc.) sit alongside Ergo's. Miner share computed as remainder so no nanoYOLO is lost to integer division across the three non-emission outputs.

Phase 3.4 — Storage rent params Done

  • storage_period: 1,577,880 blocks (1 year at 20 s) — down from Ergo's 1,051,200 (4 years at 120 s).
  • storage_fee_factor: 312,500 nanoYOLO/byte/period — exactly 1/4 of Ergo's. Annualized per-byte cost is identical.
  • ProtocolParams::from_active_for_network: network-aware variant so block-processing picks the right period per chain.

Emission .5-fix Done

Caught during Phase 4.3 design: the original schedule (6 halvings) produced a fractional .5 YOLO in the total genesis supply because 1.5625 × 1,577,880 = 2,465,437.5 is non-integral (1,577,880 is divisible by 8 but not 16). Fix: drop the halvings == 5 arm from emission.es — halvings collapse straight to the 1-coin tail floor at boundary 5.

New total supply: 176,525,325 YOLO (clean integer; 887,558 less than the original 177,412,882.5 projection). 63/63 Python tests + 51 chain-spec tests pass after the fix.

Phase 4.3 — Genesis emission box Done

Single emission box at genesis:

  • value = 176,525,325,000,000,000 nanoYOLO
  • ergoTree = canonical emission.es bytes
  • tokens[0] = singleton emission NFT, id = blake2b256("SigmaChain testnet emission NFT v1") — deterministic so any verifier can recompute it
  • R4 = Coll[Byte] holding blake2b256(treasury_accumulation.es bytes)
  • R5 = Coll[Byte] holding blake2b256(lp_accumulation.es bytes)

Treasury and LP accumulation boxes are NOT created at genesis — emission.es creates them fresh as OUTPUTS(1) / OUTPUTS(2) of every coinbase emission tx. Genesis state thus carries exactly one box.

JSON lives at test-vectors/sigmachain-testnet/genesis_boxes.json; both ergo-chain-spec and ergo-node include_str! it.

Phase 4.4 — 4-output YOLO coinbase builder Done

build_yolo_emission_tx in ergo-mining/src/coinbase.rs alongside the existing build_pre_eip27_emission_tx (Ergo path untouched for byte-parity). 1 input / 4 outputs:

  • OUTPUTS(0) — new emission box, value = input − block_reward, with input's script + tokens + R4/R5 preserved
  • OUTPUTS(1) — treasury accumulation box, value = block_reward × 10%
  • OUTPUTS(2) — LP accumulation box, value = block_reward × 5%
  • OUTPUTS(3) — miner reward box, value = block_reward − treasury − lp (≈ 85%, computed as remainder)

Phase 4.5 — Miner-only storage rent consensus rule Done

New block-level rule: any non-coinbase tx that opts into the storage-rent path (empty proof + context-extension variable 127 on any input) causes the block to be rejected with NonCoinbaseStorageRentClaim { tx_index, input_index }.

Miners sweep rent inside the coinbase by appending rent-eligible inputs after the emission box and recreated outputs after the four positionally-constrained emission outputs. Gated by BlockValidationContext::enforce_miner_only_storage_rent — false on Ergo paths (byte-parity preserved), flipped true at the SigmaChain validation boundary.

Trustless Peg — Architecture Spike (2026-06-05)

Verification — design is feasible on shipped primitives Done

Confirmed the cryptographic + protocol substrate needed for a trustless YOLO ↔ Ergo bridge is fully present in the current YOLO Rust node:

  • Sigma 6.0 / EIP-50 primitives are wired and active by default in ergo-sigma: Header.checkPow, Global.powHit, Global.decodeNbits, Global.deserializeTo[T] — implemented, cost-pinned, soft-fork-gated against activated_script_version (= 3 by default in evaluator/types.rs).
  • Autolykos2 parameters are byte-identical to Ergo (k=32, NBase=2²⁶, INCREASE_START=600·1024, etc.) — verified against ergo-crypto/src/autolykos/common.rs and the ~9k mainnet headers in ergo-crypto/tests/pow_mainnet.rs.
  • Header wire format is byte-identical to Ergo — diff -q against arkadianet v0.3.0 returned no output. header.checkPow on YOLO works on Ergo headers and vice versa without manual byte slicing.
  • Cross-chain confusion impossible by construction — each relay box is anchored at the foreign chain's genesis block-id; mis-chain headers fail the parent-lookup AVL check.

Memory saved to memory/project_yolo_node_inheritance.md so future sessions don't re-verify.

Upstream node fix — arkadianet/ergo PR #13 Open

Found a real upstream bug while parse-testing the bridge sketches through YOLO's Rust ergo-ser: method_explicit_type_args_count gated v6 explicit-type-args reads on tree_version >= 3, but the Scala 6.0 compiler emits v6 method calls inside v0-header trees (header byte 0x10). The gate caused real 6.0-compiled trees to mis-align after MethodCall args — the trailing type-arg byte got mis-interpreted as the next expression's opcode (0x68 = SHeader code → spurious "value deserialization not supported for SHeader").

Fix: type-arg count now governed purely by (type_id, method_id). Soft-fork rejection of v6 methods on non-EIP-50 chains continues to happen at evaluation time. Two pre-existing tests that pinned the buggy gate behavior updated and renamed. 314/314 ergo-ser tests pass on clean arkadianet HEAD + fix.

  • PR: arkadianet/ergo #13 — from Degens-World/ergo:fix/v6-method-typeargs-tree-version-gate
  • YOLO's local fork already has the fix on sigmachain-node-fork — unblocks bridge work immediately, doesn't need to wait for merge
  • YOLO-side regression test added at ergo-sigma/tests/bridge_sketches_parse.rs — flips green once PR merges + rebase happens

ErgoScript Rust Compiler (cannonQ/sigma-rust)

Status: production-ready, awaiting upstream PR Wired into SigmaChain build

The ergoscript-compiler crate on the workstream-f branch is production-ready: 233/233 lib tests, 164/164 conformance tests, 45/46 legacy contracts byte-match Scala, 10/15 of the "sig-15" significant Ergo contracts byte-match locally, 97.8% match across 575 generated programs in the differential fuzzer.

Two compilation modes:

  • compile(source, env) — pure Rust, no network. 45/46 contracts byte-match Scala exactly.
  • compile_canonical(source, env, node_url, api_key) — falls back to the Scala node when local bytes diverge, guaranteeing identical P2S addresses to the Scala toolchain.

Used by SigmaChain: 07-sigmachain-node/sigmachain-genesis-tool/ calls compile_canonical against localhost:9053 to produce the three canonical ErgoTree byte arrays baked into ergo-chain-spec::yolo_genesis_scripts. The runtime node has zero compiler dependency — compilation is build-time only.

PR #862 was closed 2026-05-26; smaller-PR resubmits + maintainer conversation in progress. The fork is at github.com/cannonQ/sigma-rust; SigmaChain pins rev 7ea8dc7d for reproducibility.
